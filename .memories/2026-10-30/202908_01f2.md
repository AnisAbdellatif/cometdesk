## H.265 support + encoder controls (uncommitted, verified locally)

**WHAT**
- Presets are bitrate-only (`QualityPreset::bitrate`); GUI video menu has separate fps / bitrate fields + Apply (sends only changed fields). CLI `quality --fps/--bitrate`.
- `StreamerRuntime::source_fps()` reads `source.real_resolution` (`WxH@HZ`), not `captured_fps` (measured, dips, follows desired_fps).
- macOS QoS USER_INTERACTIVE on decode thread + tokio workers (`cometdesk_view::set_user_interactive_qos`).
- H.265: `VideoFormat` + `Session::set_video_format` (config + streamer param `video_format`), CLI `codec [h264|h265]`, GUI Codec menu (restarts stream on change), viewer prefers device codec; str0m `enable_h265` offered first with H.264 fallback (Pion/Janus), Janus watch `video_format`, codec-aware keyframes; `FrameTracker` stats (codec, kbps, avg keyframe/delta bytes) in GUI stats line and `view --bench`.

**WHY:** user wants to compare H.264 vs H.265 on real device.

**Verified:** workspace clippy -D warnings clean, tests pass, release build OK. Not run on device.
