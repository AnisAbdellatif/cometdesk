## Latency/bandwidth review: video + M&K (in progress)

**WHAT:** Reviewed client paths for optimization headroom; read live device state (read-only).

**Client already lean:**
- HID: winit `window_event` → `InputMapper` → `HidSender` → `Coalescer` (120 Hz latest-wins abs moves) → `/api/ws`, Nagle disabled (`connect_async_tls_with_config(.., disable_nagle=true, ..)`), one flush per wakeup.
- Video: decode thread + one-slot mailbox, `PresentMode::Immediate`, `desired_maximum_frame_latency: 1`, zero-copy IOSurface; net→screen 1.4–2.0 ms. Host cursor is not hidden over video (acts as local cursor).

**Live device (2026-10-30):** `desired_fps=30`, `h264_bitrate=3000`, `h264_gop=30` (= our `QualityPreset::Low`), `venc_mode=smart`, `zero_delay=true`, `video_mode=direct_h264`, `mouse_polling=10`, `hid_over_datachannel=true`, `fec_packets=20`, features h265=true, `desired_fps` max 70.

**Candidate levers found so far:**
- fps 30 → 60 (device-wide): ~8 ms average encoder/frame-interval saving.
- `QualityPreset::High/Max` set fps to `limits.desired_fps.max` (70) on a 60 Hz source: should cap at source fps.
- No thread QoS set on decode/network threads (macOS USER_INTERACTIVE).
- Direct over remote TCP: device-side cwnd validation / slow start after idle, 32-frame queue + kernel send buffer → bufferbloat; firmware sysctl/TCP_NOTSENT_LOWAT levers (need root).
- Pion FEC groups of 16 packets ≈ 270 ms on a static screen vs 250 ms `REORDERING_TIMEOUT`.
- Proposed software latency bench: input → first larger delta frame; Caps Lock → `hid.keyboard.leds` event for HID-only round trip.
